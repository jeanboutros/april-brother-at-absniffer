## Description
Add a stateful event detection engine that tracks BLE devices over time and emits events (device appeared, device lost, iBeacon region enter/exit, rssi changed, new payload, exposure notification, battery low, sensor reports). Events are written to a file or stdout as JSONL.

**Key design decisions needed:**
1. device_lost requires timer — main loop is reactive-only; must process events on NO_DATA tick
2. iBeacon region enter/exit needs RSSI hysteresis (dual-threshold) + temporal debounce, not simple threshold
3. rssi_changed needs exponential moving average (EMA) before delta + per-MAC cooldown to avoid flood
4. new_payload must be scoped by (MAC, adv_type) tuple, not per MAC alone
5. Apple Find My battery is encrypted — impossible to extract; only AirPods battery accessible
6. Ruuvi v5, Xiaomi MiBeacon encrypted — need per-device keys; defer to Phase 2
7. Unbounded memory growth — need LRU eviction policy for per-MAC state (10K+ MACs in busy environments)
8. Duplicate packet filtering — same ad on channels 37/38/39 appears 3× per advertising event; deduplicate within 100ms window
9. --events - + --json on same stdout = interleaved streams; need type discriminator

**Phase 1 implementation (this ticket):**
- Core events: device_appeared, device_lost, device_returned, rssi_changed, new_payload
- iBeacon region enter/exit (with hysteresis + debounce)
- Exposure notification detection (service UUID 0xFD6F)
- Battery low (AirPods only; Find My excluded — encrypted)
- Sensor reports (Ruuvi v3 only; v5/Xiaomi deferred — encrypted)

**Phase 2 (deferred — requires per-vendor encrypted protocols):**
- Xiaomi MiBeacon (per-device encryption key)
- Ruuvi v5 encrypted format (device key)
- sensor_alert generic threshold system (needs its own RFC)

**Implementation plan:**
1. Define EventType enum and Event struct with to_jsonl() serialization
2. Implement DeviceEventTracker — stateful tracker per MAC with injectable clock
3. Add EventConfig struct for typed thresholds (lost, return, rssi_change, battery_low)
4. Implement core event detectors: device_appeared, device_returned, device_lost, rssi_changed, new_payload
5. Implement iBeacon region enter/exit detector (dual-threshold hysteresis + temporal debounce)
6. Implement exposure_notification detector (service UUID 0xFD6F)
7. Implement battery_low detector for Apple AirPods
8. Add Ruuvi v3 parser for temperature/humidity/pressure
9. Add device_lost periodic timer using NO_DATA tick in main loop
10. Add --events FILE|-, --lost-threshold, --return-threshold CLI flags
11. Share DeviceTracker state between --stat and event engine to avoid dual tracking
