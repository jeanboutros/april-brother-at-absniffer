## Description

During the psc-0029 review (C2-SW finding F3, confidence 75), the Software Engineer identified that the `BluetoothATDriver` constructor call at `main.cpp:123` is not wrapped in a try-catch. If the constructor throws `std::invalid_argument` (e.g., the port became closed between `init()` and construction), the exception would propagate uncaught and terminate with a non-helpful error message.

### Current Code

```cpp
// main.cpp:123
ble_sniffer::BluetoothATDriver driver(std::move(port));
```

In the current flow, this path is practically unreachable because `init()` just succeeded on the line above. However, defense-in-depth is a security best practice. If the code flow changes in the future (e.g., another operation between `init()` and construction), the uncaught throw could cause `std::terminate`.

### Suggested Fix

Wrap the constructor call in a try-catch:

```cpp
try {
    ble_sniffer::BluetoothATDriver driver(std::move(port));
    // ... rest of driver operations ...
} catch (const std::invalid_argument& e) {
    std::cerr << "Error: " << e.what() << std::endl;
    return 1;
}
```

This is a minimal, low-risk change that adds defense in depth.
