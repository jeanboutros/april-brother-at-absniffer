## Acceptance Criteria
1. --events flag accepts FILE, - (stdout), or none as values
2. --events=none creates NullEventEmitter that discards all events (zero CPU overhead)
3. --events=none is the default behavior (events are opt-in)
4. CLI11 validates --events values with clear error message
5. Build passes

## Description
Add `--events=none` (or `--no-events`) to suppress event stream output. This is useful for headless operation where only raw packet data is needed, or for reducing CPU load on constrained devices like Raspberry Pi.

**Key design decisions needed:**
1. If events are opt-in (--events FILE required), --no-events is redundant. Clarify: do events auto-enable during replay?
2. Does --no-events suppress generation or just output? Suppressing generation saves CPU; suppressing output only is safer.
3. Better UX: --events FILE|-|none instead of separate --no-events flag.

**Recommendation:** Use `--events FILE|-|none` unified syntax. This deprecates a separate `--no-events` flag and scales better.

**Implementation plan:**
1. Implement as --events=FILE|-|none instead of separate --no-events flag
2. When --events=none, instantiate a NullEventEmitter (no-op) instead of real engine
3. Add CLI11 validation for the flag values
