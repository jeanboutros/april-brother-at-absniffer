## Description

During the psc-0029 review (C2-SW finding F1, confidence 70), the Software Engineer identified that several `void` methods in `BluetoothATDriver` silently no-op when the port is disconnected (`!is_connected()`). This is the same class of bug that psc-0029 fixed at the constructor level — the constructor now throws `std::invalid_argument` when the port is not open, but the runtime methods still silently degrade.

The affected methods are:

| Method | Line | Current behavior when disconnected |
|--------|------|-----------------------------------|
| `send_command()` | 33 | Silently returns (no error, no log) |
| `start_scan()` | 109 | Silently returns |
| `stop_scan()` | 113 | Silently returns |
| `set_baud_rate()` | 118 | Silently returns |
| `set_scan_mode()` | 131 | Silently returns |
| `reset_device()` | 136 | Silently returns |

Each method has the pattern `if (!is_connected()) return;` which produces no feedback to the caller that the operation was not performed.

### Design Decision Required

The fix direction (bool return vs exception vs logging) requires an ADR. Options include:
- **Option A:** Return `bool` from each method — consistent with `init()` pattern, callers can check
- **Option B:** Return `std::expected<void, Error>` — more type-safe, requires C++23 or library
- **Option C:** Log a warning to stderr and continue returning void — minimal change, adds observability
