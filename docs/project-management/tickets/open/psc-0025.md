## Description
Implement the reusable `presence_analyzer` module with zero BLE dependency. This module classifies devices across three time scales (Session, Daily, Long-term) using pluggable classifiers. It operates on generic types (`PresenceSample`, `DeviceId`, `PresenceFeatures`) so it can be reused for WiFi, Zigbee, or any other signal type.

**Key components:**
- `PresenceTimeline`: time-ordered sequence of `PresenceSample` per device
- `feature_extraction` namespace: pure functions (`extract_presence_features`, `extract_temporal_features`)
- `PatternClassifier` interface: pluggable classification with `RuleBasedClassifier` implementation
- `PresenceAnalyzer` orchestrator: builds timelines, extracts features, classifies behavior
- `SessionProfile`, `DailyProfile`, `LongTermProfile`: profile types with confidence scores
- `DeviceBehavior` enum: FIXED_DEVICE, PASSING_DEVICE, SCHEDULED_DEVICE, RESIDENTIAL_DEVICE, INTERMITTENT_DEVICE, UNKNOWN

**Classification behavior per AGENTS.md:**

| Behavior | Key Features | Min Data Needed |
|----------|-------------|-----------------|
| FIXED_DEVICE | duty_cycle ≈ 1.0, signal_variance < 2 dB² | 1 session |
| PASSING_DEVICE | duty_cycle < 0.1, 1–2 sessions, brief | 1 session |
| SCHEDULED_DEVICE | 3+ short sessions/day, regular times | 1+ days |
| RESIDENTIAL_DEVICE | duty_cycle 0.3–0.8, morning-absent/evening-present | 2+ days |
| INTERMITTENT_DEVICE | no clear pattern | 3+ days |
| UNKNOWN | insufficient observations | any |

**Architecture constraints:**
- No BLE-specific headers — module must compile without `bluetooth_at_driver.h`, `messages.h`, or `types.h`
- Pure functions in `feature_extraction` namespace — no state, no I/O, maximally reusable
- `PatternClassifier` is a pluggable interface — `RuleBasedClassifier` is the default, `AIClassifier` is the extension point
- `PresenceAnalyzer` uses dependency injection for Clock and PatternClassifier
