## Acceptance Criteria
1. Driver detects serial disconnect (read() returns 0 with errno indicating disconnect, or poll() POLLERR/POLLHUP)
2. DriverState enum exposed via state() accessor
3. try_reconnect(timeout) attempts reconnection with exponential backoff
4. read_buffer is cleared on disconnect (no stale data)
5. --reconnect-timeout CLI flag controls reconnect timeout (0 = no reconnect, default)
6. After successful reconnect, scan mode is restored (AT+SCAN1 re-issued)
7. Build passes

## Description
Add disconnect detection and automatic reconnection for USB serial disconnects. The ABSniffer dongle may disconnect when the USB cable is unplugged, the hub loses power, or the OS suspends. Currently, the driver silently enters an invalid state with no recovery path.

**Key design decisions needed:**
1. Disconnect detection method: errno-based heuristic vs poll() with POLLERR/POLLHUP vs AT probe command
2. USB device re-enumeration at different path — only try original path, or add device discovery?
3. Scan state persistence across disconnect — does ABSniffer keep scanning? Must re-issue AT+SCAN1?
4. Baud rate state lost if device reboots — must store and re-apply last requested config
5. Read buffer clearing on disconnect to avoid stale partial data corrupting next parse
6. Debounce for flaky USB (rapid connect/disconnect cycles)

**Implementation plan:**
1. Add disconnect-specific errno checks in read_line() (EBADF, ENODEV, EIO, ENXIO)
2. Add DriverState enum (CONNECTED, DISCONNECTED, RECONNECTING, FATAL_ERROR) and state() accessor
3. Add try_reconnect(timeout) method with exponential backoff
4. Clear read_buffer on disconnect
5. Add --reconnect-timeout CLI flag; integrate reconnect into scan loop
6. Re-issue AT+SCAN1 after successful reconnect
