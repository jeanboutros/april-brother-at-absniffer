## Acceptance Criteria
1. `--json` flag produces valid JSONL on stdout, one JSON object per line
2. `--json` and `--stat` are mutually exclusive with clear error message
3. SIGPIPE is handled (process survives pipe consumer closing)
4. Non-scan messages produce JSONL error/event lines on stderr or as JSONL events
5. JSONL output includes: timestamp (ISO 8601), MAC (**raw hex** — `"123B6A1AF0E6"` not `"12:3B:6A:1A:F0:E6"`), RSSI, adv_type, data_length, adv_data (hex)
6. Every JSONL packet line includes `"type":"packet"` field (ADR psc-adr-0003)
7. PacketSink interface exists with `write()` and `flush()` methods
8. StdoutJsonlSink and FileJsonlSink implementations exist
9. Build passes

## Description
Add a `--json` CLI flag that switches output from human-readable TUI to JSONL (JSON Lines) on stdout. This enables pipe-consuming tools like `jq`, `awk`, or custom scripts to process BLE scan data programmatically.

**Key design decisions needed:**
1. Where do errors go when stdout is JSONL? Define error reporting strategy (stderr vs JSONL error event)
2. SIGPIPE handling — must add `signal(SIGPIPE, SIG_IGN)` when writing to stdout
3. `--json` and `--stat` must be mutually exclusive (both claim stdout)
4. JSONL schema versioning — should there be a `"schema_version"` field?
5. Non-scan messages (ERROR, STATUS) need JSONL event lines or are silently dropped

**Implementation plan:**
1. Extract `JsonlCaptureWriter` from main.cpp into library as `PacketSink` interface
2. Create `StdoutJsonlSink` and `FileJsonlSink` implementations
3. Add `--json` flag; suppress human-readable output when active
4. Make `--json` and `--stat` mutually exclusive
5. Handle SIGPIPE (pipe consumer closes)
