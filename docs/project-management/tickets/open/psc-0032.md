## Acceptance Criteria

1. When `--stat` is used without `-s` (scan mode), the program either: (a) starts scanning automatically and then shows stats, or (b) prints a clear error message to stderr explaining that `--stat` requires `-s` and exits with non-zero code
2. The chosen behavior is documented in the CLI `--help` output
3. Build passes with zero errors and zero warnings
4. The code changes are reviewed through the full pipeline (A→B→C→C4)

## Description

During the psc-0029 A-GATE review (advisory item M2), it was identified that using `--stat` without `-s` (scan flag) produces confusing behavior. The `--stat` flag is intended to show scanning statistics, but it can be invoked without actually starting a scan, leading to confusing output or no output.

This is a UX gap — the CLI should either:
- **Option A:** Make `--stat` imply `-s` (auto-start scanning when stats are requested)
- **Option B:** Validate that `--stat` requires `-s` and print an error if used alone

The decision requires UX consideration (Option A is more convenient, Option B is more explicit).
