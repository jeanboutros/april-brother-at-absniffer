4. nlohmann_json is CLI-only dependency (not in library conanfile.py)
5. --replay-speed flag controls replay timing (instant, realtime, custom multiplier)

7. Corrupted/malformed JSONL lines are skipped with warning, not crash
8. End-of-stream exits cleanly with summary
9. Build passes

## Description
Add the ability to read previously captured JSONL files as input, enabling offline analysis, debugging, and testing of scan processing logic without requiring physical hardware.

**Key design decisions needed:**
1. MAC format mismatch — writer emits colons ("12:3B:6A:1A:F0:E6") but parser expects raw hex ("123B6A1AF0E6"). Must fix writer or add colon-stripping in replay parser.
2. JSON parser scope — keep nlohmann_json in CLI executable only, not the library
3. ScanResultMessage needs from_fields(mac, rssi, adv_type, data_length, adv_data) factory for replay
4. Timestamp monotonicity — detect and skip backward timestamps
5. End-of-stream behavior — emit summary and exit cleanly vs run forever
6. Corrupted last line handling — graceful degradation, skip malformed lines
7. Make device arg and -i FILE mutually exclusive

**Implementation plan:**
1. Add PacketSource abstract interface (read_line(), is_exhausted(), start())
2. Make BluetoothATDriver implement PacketSource
3. Create JsonlReplaySource — reads JSONL file, reconstructs ScanResultMessage
4. Add JSON parser dependency (nlohmann_json — CLI-only, not library)
5. Add --replay-speed flag (instant/realtime/N×)
6. Make device arg optional when -i provided; add mutual exclusivity validation
7. Refactor scan loop to use PacketSource* instead of direct driver.read_line()
