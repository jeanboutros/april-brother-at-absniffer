## Issue Description
The public library header `bluetooth_at_driver.h` includes `<termios.h>` and exposes `speed_t sniffer_baud_rate = B115200`. While the project is POSIX-only (Linux + macOS), this has two problems:
1. `speed_t` and `B115200` are POSIX macros with platform-varying definitions — they shouldn't be in a clean public API
2. Including `termios.h` in the public header makes it impossible to create a mock `SerialPort` for testing without pulling in the entire POSIX serial stack

## Issue Analysis
```cpp
// bluetooth_at_driver.h line 38 — POSIX header in PUBLIC API
#include <termios.h>

// Line 45-46 — POSIX types in public constants
constexpr speed_t sniffer_baud_rate = B115200;  // speed_t varies by platform
constexpr int sniffer_timeout = 1000;
```

## Change Suggested
- Remove `#include <termios.h>` from the public header
- Move `sniffer_baud_rate` to `.cpp`; replace public constant with `constexpr int sniffer_baud_rate_bps = 115200` (the numeric baud rate)
- Keep `sniffer_timeout` in the header but as `constexpr int` (it already is)
- In `init()`, use `B115200` directly (now inside the `.cpp` where `<termios.h>` is included)

### F9 Analysis: `tcdrain`/`tcflush`/`tcsetattr` in `close_connection()`

Per the POSIX termios(3) man page, ALL three functions return -1 on error and set errno. They are C functions that do NOT throw C++ exceptions. Specific failure modes:

| Function | Can fail? | Failure mode | In `close_connection()` |
|----------|-----------|--------------|------------------------|
| `tcdrain(fd)` | Yes — returns -1, sets `EBADF`/`EINTR` | Can block indefinitely waiting for output to drain. `EINTR` if interrupted by signal. | **Removed** — blocks in destructor paths, unnecessary for USB serial close. |
| `tcflush(fd, TCIOFLUSH)` | Yes — returns -1, sets `EBADF`/`EINVAL` | Cannot block. Failure is harmless during close. | Kept as best-effort (return value ignored). |
| `tcsetattr(fd, TCSANOW, ...)` | Yes — returns -1, sets `EBADF`/`EINVAL` | Cannot block. Failure to restore original settings is cosmetic. | Kept as best-effort (return value ignored). |

**Conclusion:** `tcdrain` was correctly removed (blocking risk). `tcflush` and `tcsetattr` failures during close are safely ignored since the fd is always closed afterward.
